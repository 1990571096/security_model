# 简历项目与面试讲解提纲

更新时间：2026-09-10

## 1. 项目一句话介绍

面向数据清洗的安全模型训练系统是一个将 Java 任务平台与 Python 安全算法运行时解耦的实验管理平台。
系统围绕 LDD 训练前数据清洗，提供数据集资源管理、实验任务编排、异步执行、失败重试、参数快照、
运行日志、实验报告和清洗后数据集导出能力。

## 2. 业务背景

安全算法通常依赖独立的 Python、PyTorch、数据集和模型环境，直接把研究脚本塞进 Web 请求会带来
请求超时、进程失控、结果不可追溯和失败后难以恢复等问题。本项目将一次算法运行抽象为可管理的
实验任务，使算法代码负责计算，平台负责资源校验、状态流转、运行隔离和结果展示。

当前展示范围只保留论文提出的 LDD 训练前防御算法，避免多个算法同时接入导致业务边界模糊。
后续算法沿用同一个执行器和结果协议即可接入。

## 3. 核心模块

| 模块 | 主要职责 |
| --- | --- |
| 资源管理 | 管理数据集、算法、模型和超参数模板 |
| 任务编排 | 创建任务、校验参数、启动、取消、重试和查询状态 |
| 执行器适配 | 通过 `DefenseTaskExecutor` 调用 Python/PyTorch 算法 |
| 运行隔离 | 按任务、尝试次数和 `run_id` 隔离请求、结果和日志 |
| 实验追溯 | 保存启动时资源、配置、运行环境和结果快照 |
| 报告展示 | 将 LDD 指标、样本统计、产物和执行尝试可视化 |
| 数据资产导出 | 根据保留索引异步重建 CIFAR-10 清洗子集并下载 |

## 4. 可以重点介绍的后端设计

### 4.1 任务状态机

训练任务使用：

```text
pending -> running -> success
                    -> failed -> pending（受控重试）
                    -> canceled
```

导出任务使用：

```text
pending -> running -> success
                    -> failed -> pending（重新提交）
```

状态流转通过数据库条件更新保护。即使用户重复点击启动，只有一个请求可以成功领取
`pending` 任务；运行回调还必须携带当前 `run_id`，旧尝试的迟到回调会被忽略。

### 4.2 Java 与 Python 解耦

Java 侧不直接依赖 `LDD.py` 的函数调用，而是生成标准化 `request.json`，由 Python 适配器
读取请求并写出标准化 `result.json`。适配器负责把平台参数映射到 VaB 原始代码，平台负责
任务状态、日志、产物和报告。

这种边界使得后续替换为其他 Python 算法、Shell 进程、RPC 服务或消息队列 worker 时，
Controller 和任务业务代码不需要重写。

### 4.3 参数快照与可复现

启动任务时，平台把数据集、算法、超参数模板、任务自定义配置、Python 环境和运行标识冻结到
执行快照中，并对可访问的数据集文件记录 SHA-256 内容摘要。后续修改资源表不会改变已经启动的历史实验。
配置合并顺序为：

```text
算法默认配置 -> 超参数模板 -> 任务自定义参数
```

LDD 参数在进入异步执行器前执行 JSON 对象、白名单、必填项、类型和范围校验。同时，服务层禁止删除
仍被任务引用的数据集、算法和超参数模板，保证历史实验报告与重试现场可继续访问。

### 4.4 失败重试与重启恢复

每次启动使用新的 `run_id`、递增 `attempt` 和独立目录。失败任务只允许通过受控接口重新进入
`pending`，不会覆盖上一轮参数快照和日志现场。

应用重启后，平台无法安全接管原 Python 进程，因此将遗留的 `running` 任务收敛为带错误码的
可重试失败；导出任务的 `pending` 记录会重新派发，`running` 记录会收敛为失败。异步执行池
使用有界队列和拒绝策略，任务或导出任务无法进入执行池时，会分别记录 `TASK_QUEUE_FULL` 或
`EXPORT_QUEUE_FULL`，避免出现“接口已返回但任务永久等待”的悬挂状态。

### 4.5 产物安全

算法结果是外部进程产生的不可信数据。平台读取 PNG、日志、索引和 ZIP 前，会把路径解析为
真实路径，并验证其位于当前任务产物根目录内；导出使用 `.part` 临时文件，成功后再原子移动
为正式文件，避免下载到未完成的压缩包。

## 5. 一次任务的讲解顺序

1. 管理员登记 CIFAR-10 数据集和 LDD 算法。
2. 创建任务并选择批次大小、轮数、攻击方式和清洗参数。
3. 后端检查资源状态、算法阶段和参数范围，写入执行快照。
4. 数据库原子领取任务，生成 `run_id`、`attempt` 和任务目录。
5. Python 适配器运行 LDD，持续写入 stdout/stderr 和结构化结果。
6. 后端校验结果协议，更新任务状态并保留日志、索引和图像产物。
7. 前端展示进度、指标、快照和报告。
8. 用户提交指定隔离比例的异步导出任务，系统根据索引重建干净 CIFAR-10 子集并下载。

## 6. 简历描述示例

**面向数据清洗的安全模型训练系统｜Spring Boot、MySQL、Redis、Vue、Python/PyTorch**

- 负责将网络安全竞赛算法重构为可视化实验平台，围绕 LDD 训练前数据清洗实现资源管理、
  任务编排、实验报告和清洗子集导出闭环。
- 设计 `DefenseTaskExecutor` 统一执行器契约，使用 JSON 请求/结果协议解耦 Java 业务服务与
  Python/PyTorch 算法运行时。
- 基于数据库条件更新、`run_id`、`attempt` 和任务专属目录实现并发启动保护、失败重试和迟到
  回调隔离；通过启动快照保证实验参数和资源可追溯。
- 通过运行环境指纹、数据集 SHA-256 内容摘要和资源引用保护增强实验可复现性与历史数据完整性。
- 在 LDD 结果中记录 Python、PyTorch、NumPy、CUDA、GPU 和关键依赖版本，并在报告页展示算法实际运行环境。
- 实现 Python 进程超时回收、任务取消、应用重启恢复、stdout/stderr offset 增量读取和异步
  CIFAR-10 清洗子集导出。
- 提供任务执行池观测接口和任务中心状态条，展示活跃线程、队列容量、完成数及饱和状态；
  对线程池拒绝进行数据库状态收敛和可重试失败记录。
- 对外部算法产物执行真实路径 containment 校验和临时文件保护，降低任意文件读取及未完成
  文件下载风险。

## 7. 面试时需要诚实说明的边界

- 当前真实演示只开放 LDD，VS、训练中防御和训练后防御没有放入主流程。
- 当前执行模型是单机本地 Python 进程和 Spring 异步线程，尚未引入消息队列、分布式 worker
  和 GPU 资源调度。
- 当前工程验证使用小批次和小轮次配置，不能直接替代论文正式实验结论。
- Spring Boot 3、Java 17、Vue 3 迁移已规划，当前先完成协议与迁移准备，再在独立分支中执行框架升级。

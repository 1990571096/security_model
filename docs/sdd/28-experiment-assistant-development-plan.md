# 实验助手开发与验收方案

**定位为技术扩展，可以按本方案实施。** 以现有实验报告和失败记录作为演示场景，验证大模型接入、结构化意图解析、多步工具编排、RAG 引用、多轮上下文、权限校验和模型故障降级。交付以技术能力和可复现演示为准，实用性作为可选观察项。

**本次实施结果与可复制演示见 [29-experiment-assistant-acceptance.md](29-experiment-assistant-acceptance.md)。**

## 1. 交付目标

让实验人员从已有运行出发，在同一个助手中完成「判读报告 → 选择清洗子集 → 对照多次运行 → 拟定下一轮 → 保存实验笔记」。失败任务从详情页进入同一助手，给出该次尝试的失败阶段、已确认事实和优先检查项。

| 用户问题 | 可验收的产出 |
| --- | --- |
| 「这次保留 30% 还是 60%，我想先做下游验证」 | 两组实际纯度、样本数、导出可用状态和原报告入口。根据用户给出的样本量或纯度目标筛选；目标不够明确时先展示取舍，再问一个关键条件。 |
| 「这三次运行差在哪？先只看 30%」 | 用户所选运行的实际配置差异、同口径指标表、可比较范围和证据缺口。 |
| 「下一轮只看训练轮数的影响」 | 基线运行、唯一拟改变变量、应固定的条件和待测指标；生成可在现有任务页面检查的参数草案。 |
| 「这次失败，修好后怎么判断能否重试？」 | 本次尝试的证据时间线、可能阶段、核对步骤和对应详情入口。 |
| 「把刚才的结论和下一步保存下来」 | 私有实验笔记，含运行身份、当时的指标、出处、已知缺口和下一步计划，可重新打开和导出 Markdown。 |

任务列表、进度和下载走现有业务页面。助手提供跳转、参数草案和明确的分析结果。创建、启动、取消、重试和导出均由用户通过现有页面提交，业务服务执行授权和状态校验。

技术演示从报告页进入同一对话。用户选定第二个运行后，助手读取两次报告，按相同保留比例计算差值，并在追问中保留选定的运行。调用记录可核对每一步的工具、结果和证据出处。将模型切换为不可用状态后，用同一组已选运行复验服务端对照结果。

## 3. 实验方案

### 3.1 主场景复验

使用已有正式 5 epochs 运行 `2122901116713205761` 的可授权报告、快照和产物记录。隔离环境可以导入脱敏证据作为只读样本，保留来源提交和原始运行引用。报告缺失或产物不可读时，在测试记录中注明缺口。正式运行的已知指标以 [真实验收记录 §8](25-ldd-real-acceptance-checklist.md#8-正式-5-epochs-执行结果2026-11-18已通过) 和实际报告为准。

1. 从该报告进入助手，提问「30% 和 60% 我该选哪个」。核对两档纯度、样本数及现时导出状态。正式记录给出了对应纯度 `100.00%` 和 `99.99%`，样本数从该次报告的逐比例字段取值。没有下游准确率或攻击成功率测量时标记为「未采集」。
2. 追问「我至少需要 2 万张，哪些档位可用」。检查助手用记录的样本数筛选符合条件的档位，并解释导出资格、导出任务正在处理和下载已就绪三个状态。没有足够信息时显示缺失字段。
3. 追问「把另一次运行作为基线，只看 30%」。从当前用户能访问的候选中显式选择对照运行。对照表分别给出实际配置变化、可展示的指标差和能否归因。已有 1 epoch 运行可作候选，比较前逐项核对输入、实现版本和参数。
4. 追问「下一轮只改训练轮数，把计划保存下来」。生成对照计划并打开现有任务表单。检查参数合并与服务端校验结果。保存并重开笔记，能返回原报告、查看当时的指标与证据缺口。

### 3.2 下一轮科研对照草案

| 对照项 | 设定与记录 |
| --- | --- |
| 问题 | 在相同输入及其他配置下，训练轮数变化对应的清洗指标差异有多大。 |
| 分组 | 历史正式 5 epochs 记录作为候选基线。以 1 epoch 和 5 epochs 组成成对配置。历史运行的冻结条件可以核对时复用，缺口保留在计划中。 |
| 控制变量 | 固定数据内容清单、数据拆分、算法实现版本、其余有效参数和评估口径。同一对内使用相同种子，先用已有 `123` 做流程核对。需要评价稳定性时，使用多组预先登记的种子重复配对。 |
| 评估 | 预先选择共同的保留比例，例如 `30%` 和 `60%`。记录每档清洗纯度、实际保留数和耗时。需要下游模型效果时，独立定义评估集、对照基线和评估流程，随后从实测报告读取准确率和攻击成功率。 |
| 产物 | 保存每次运行的快照、版本、运行引用、报告和子集导出引用，记录每对差值和缺失数据。多次重复后再汇总波动。 |

这份草案用于验证助手的规划能力。研发验收可使用已有运行、合成夹具和故障记录完成。新的实测结果由后续科研执行产生。

## 4. 数据与编排契约

- **运行引用**。统一使用 `taskId`、`runId`、`attempt`，大整数 ID 按字符串传输。历史记录只有在指标、快照和产物均能归属到所选尝试时才进入比较。重试后无法读取旧尝试的结果，返回「所选尝试不可用」并保留原选择，供用户显式切换。
- **多轮上下文**。会话单独保存用户确认的主运行、基线集合、关注比例和筛选目标。下一轮重新校验归属和资源可用状态。存在多个候选或指代不明时展示候选。会话切换、浏览器刷新、重新打开笔记都应保留已确认的选择。
- **工具计划**。页面入口给出操作和运行引用。自由文本由模型解析为受约束的 `action`、运行候选、比例和目标；服务端解析、校验并决定工具序列。支持结果判读、对照、诊断、规划和澄清。现有常用问法继续可用，路由评估覆盖改写、复合问题和追问。执行复用已有时限、配额与审计。
- **比较口径**。Java 核对数据内容版本、配置、算法版本、种子、指标定义和共同保留比例。逐项给出「一致」「不同」「未知」，说明本次比较预期改变的字段。条件缺失或多个变量变化时，允许并排看实际数据并提示归因受限。纯度差以百分点显示，样本数量差以样本数显示；缺失和零分开处理。可用多个对照运行，以用户选定的基线逐个对齐。
- **结果结构**。返回 `status`、`action`、`runs`、`metrics`、`comparability`、`gaps`、`evidence`、`nextActions`，按场景提供比较表、诊断或草案。区分「需选对象」「无法比较」「证据不足」「模型降级」。事实、计算和证据引用由服务端生成，模型负责提问与组织解释。报告、审计及知识证据可跳转核对。
- **失败诊断**。服务端优先核对本次派发、执行准备、进程、结果校验和导出的事实来源。用稳定错误码和已脱敏的本地日志分类提取信号。泛化错误码与具体异常分别记录，例如编码异常须匹配本次尝试的日志证据后再给出检查建议。证据冲突时注明冲突，列出可以缩小范围的检查。
- **参数草案**。基于所选基线生成变更前后字段，标记推断、默认值和用户指定值。打开新建表单时复用现有参数预览与业务校验，处理模板异动和资源不可用。用户提交后按现有任务流程创建为 `pending`。
- **实验笔记**。建议用独立的私有笔记实体，记录拥有者、标题、分析时间、运行引用、脱敏事实快照及下一步。用户显式保存，可查看、改名、编辑备注、删除和导出 Markdown。重开时区分保存时证据与实时状态，任何已失去读取权限的运行内容按当前权限处理。保存重试具备幂等性。
- **权限和外部模型**。助手使用现有工具的任务归属规则，覆盖每个对照对象、历史会话和笔记操作。模型只收到脱敏的必要字段和受控引用，身份字符串可在服务端映射。采用字段白名单阻断本地路径、凭据、原始日志和原始请求/结果。知识内容始终作为证据处理。外部模型故障时，明确上下文的指标表、对照判定和基础诊断继续可用。

## 5. 开发步骤

| 顺序 | 开发任务 | 阶段产出 |
| --- | --- | --- |
| 1 | 核对当前工作树、实际运行快照及报告结构。记录可用字段、缺口和当前权限边界。准备同条件、变量混杂、缺指标、陈旧尝试、越权五类夹具。 | 一份来源与字段映射，加可复用的测试数据。 |
| 2 | 建立按尝试读取的只读证据服务，完成单报告判读、子集资格、跨运行对齐和差值计算。先用确定性返回跑通主场景。 | 支持实际数据与证据跳转的直接调用接口。 |
| 3 | 接入结构化意图和多步编排，持久化选中的上下文，完成模型降级。扩展现有失败诊断，添加本次尝试的日志信号与证据缺口。 | 同一窗口支持报告分析、对照追问和失败排查。 |
| 4 | 实现对照计划、参数草案和私有笔记。需要新表时提供独立增量与回滚脚本，纳入现有初始化和隔离库门禁。 | 可回填现有任务表单，笔记可回访、编辑和导出。 |
| 5 | 接通报告页、任务多选和失败页。完成当前运行、基线、多轮追问、证据跳转、导出跳转和手机视口交互。 | 从真实页面完成主场景，无需手填运行 ID。 |
| 6 | 执行下节对照验收，补齐运行指南、权限边界和可演示数据。按提交记录代码运行版本、实测结果和待补证项。 | 可交接版本与逐项验收记录。 |

## 6. 验收矩阵

| ID | 验收动作 | 通过条件 |
| --- | --- | --- |
| EA-01 | 用真实报告或经授权的脱敏归档对照助手结果 | 每个展示值与同一次运行的实际报告一致。缺少实测的指标清楚标为未采集，来源可以打开。 |
| EA-02 | 指定样本量下限、关注比例和实际使用目标 | 推荐遵循用户目标，正确筛掉不满足条件的比例，导出状态与真实接口一致。用受支持的产物验证「打开导出」后的用户操作链路。 |
| EA-03 | 对比可对齐、数据版本未知、多变量变化及缺指标样本 | 同比例差值可复算，条件逐项对齐，缺失信息和归因边界清晰。 |
| EA-04 | 从报告提问，追问「只看 30%」「加上上次那份」并切换会话 | 用不同问法可完成同一实际操作。重复同一案例至少用三种问法，包含一个复合问题和一次追问；没有唯一指代时出现候选，确认后继续原计划。 |
| EA-05 | 用真实脱敏故障日志复验或用可控夹具覆盖编码故障、配置缺失和证据冲突 | 已确认事实、可能阶段和核对步骤各有对应证据。只有泛化错误码时保持待确认。 |
| EA-06 | 生成草案并回填，保存、重开及导出笔记 | 草案通过现有参数校验，提交前无任务或调度写入。用户点创建后得到 `pending`；笔记可回访来源，重复提交得到同一份笔记。 |
| EA-07 | 跨账号、尝试变化、权限撤销、模型异常及伪造证据测试 | A 无法取得 B 的报告或笔记内容；旧尝试不串到新运行；模型伪造数值和引用不进入用户结论；假 HTTP 捕获证明外发字段符合白名单。 |
| EA-08（可选观察） | 对照现有手工做法完成任务 | 记录一次子集选择或实验对照的耗时、页面切换和遗漏条件，作为后续产品决策参考。 |

EA-01 至 EA-07 为交付门禁。验证层级为 Java 单元、隔离 MySQL 集成、假模型 HTTP 和真实前端浏览器。浏览器验收覆盖桌面与手机、切换运行、错误与空状态。项目门禁沿用 `mvn -B -f migration-backend/pom.xml verify -Pmysql-it` 和前端 `npm run build`，Redis、RabbitMQ 依现有 workflow 启用并单独记录执行与跳过数。真实模型自然语言表现与科研运行结果按各自的证据记录。

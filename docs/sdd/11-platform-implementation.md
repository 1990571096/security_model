# 当前平台实现说明

更新时间：2026-08-24

## 1. 文档目的

本文档记录“面向数据清洗的安全模型训练系统”当前已落地的平台实现，用于指导后续功能迭代、论文系统说明和答辩演示准备。

本文档描述的是当前工程版本的实际能力，不将规划中的功能、后续拟接入算法或工程验证结果表述为已完成的论文实验结论。

## 2. 平台定位与范围

平台从早期网络安全竞赛项目重构而来，当前重点是为图像训练数据的训练前防御提供可视化管理、任务编排、算法调用和结果展示能力。

当前平台负责：

- 管理数据集、模型、算法和超参数模板等实验资源。
- 创建、校验、启动和查询训练前防御任务。
- 通过统一执行器调用外部 Python 算法。
- 将算法过程和结构化结果保存至任务记录，并在前端展示。
- 对任务产物中的 PNG 图像提供受限预览。

当前真实接入范围仅包含 LDD 训练前防御算法。训练中防御、训练后防御和其他训练前对比算法仍保留平台扩展边界，但尚未接入真实运行代码。

## 3. 当前技术实现

### 3.1 实际运行基座

为减少对原有 ELADMIN 工程的大规模改造，当前实现继续使用以下技术：

| 层次 | 当前实现 |
| --- | --- |
| 前端 | Vue 2.7、Vue CLI、Element UI |
| 后端 | Java 8、Spring Boot 2.7、Spring Security、JWT、MyBatis-Plus |
| 数据与状态 | MySQL、Redis |
| 算法运行时 | Python、PyTorch、外部 VaB 算法工程 |
| 构建工具 | Maven、npm |

目标技术栈仍是 Java 17、Spring Boot 3、Vue 3、Vite、Element Plus 和 Pinia。当前版本先稳定安全训练领域模型、任务协议和展示界面，再执行框架迁移，避免框架升级与业务重构同时发生造成返工。

### 3.2 工程模块

```text
security_model
├── eladmin/                         后端工程
│   └── eladmin-system/              安全训练资源与任务接口
├── eladmin-web/                     可视化管理前端
├── algorithm-runtime/vab/           VaB 外部算法适配器
├── docs/sdd/                        SDD 设计与运行文档
└── sql/                             数据库初始化和演示数据脚本
```

外部算法代码、数据集、模型检查点和真实任务输出不复制到平台仓库，仍由外部 VaB 项目维护。平台只维护适配器、资源引用、请求协议和结果展示。

## 4. 业务对象

| 对象 | 业务含义 | 当前用途 |
| --- | --- | --- |
| 数据集 | 训练或清洗任务所使用的数据目录及说明 | 为算法提供本地数据集根目录 |
| 模型 | 任务关联的模型资源 | 训练前任务可登记模型信息；LDD 当前主要使用 VaB 内部模型流程 |
| 算法 | 可调用的防御算法及其实现路径、默认配置和参数 schema | 当前真实路径为 `vab://pre-defense/ldd` |
| 超参数模板 | 可复用的算法配置 JSON | 覆盖算法默认配置，形成单次任务有效配置 |
| 训练前防御任务 | 一次数据风险检测和干净子集选择任务 | 记录状态、进度、输入快照和清洗结果 |
| 任务产物 | 日志、结果 JSON、索引文件、模型检查点和图像等 | 保存在任务专属外部目录，前端按任务结果展示 |

## 5. 主要业务流程

### 5.1 资源配置与任务创建

```text
管理员登录平台
  -> 登记数据集、算法、超参数模板和模型资源
  -> 创建训练前防御任务
  -> 关联数据集、LDD 算法和超参数模板
  -> 保存为 pending 状态
```

任务启动前，后端校验数据集、算法阶段和超参数模板是否存在且匹配。校验通过后，平台生成不可变的执行请求快照，而不是让算法运行时反复查询业务表。

### 5.2 训练前任务执行

```text
前端任务页
  -> POST /api/pre-defense/start/{taskId}
  -> PreDefenseService
  -> DefenseTaskExecutor
  -> PythonDefenseTaskExecutor
  -> algorithm-runtime/vab/algorithm_entry.py
  -> 外部 VaB LDD 运行环境
  -> 任务专属结果目录
  -> MySQL cleaning_result
  -> 前端任务详情页
```

任务状态当前使用 `pending -> running -> success/failed`。执行失败时，执行器将错误码、失败原因和产物目录写入结果 JSON，供前端在任务详情中展示。

### 5.3 结果查看与可视化

任务完成后，前端任务详情页从训练前任务的 `cleaning_result` 中读取结构化结果，并展示：

- 算法名称、运行时长和实验配置标签。
- 不同隔离比例下的干净子集纯度和保留样本数量。
- 任务输出目录、日志路径、选中样本索引文件和其他产物。
- 有效配置 JSON 和完整清洗结果 JSON。
- 任务产物中的 PNG 图像预览。

图像预览通过 `GET /api/pre-defense/artifact-preview/{taskId}` 提供。后端会先读取任务结果中的产物根目录，只允许访问该目录下存在的 PNG 文件，防止通过前端参数读取任意本地文件。

## 6. LDD 接入实现思路

### 6.1 统一执行器边界

后端业务层通过 `DefenseTaskExecutor` 调用算法。执行器接收 `DefenseTaskRequest` 快照，其中包含任务、数据集、算法、超参数模板和可选模型资源。

这样做的目的如下：

- Controller 和 CRUD Service 不依赖具体的 PyTorch 或 VaB 实现。
- 后续算法只需遵守相同请求与结果协议，无须重写任务管理页面。
- 任务启动时的资源与配置可被记录，便于后续实验复现。

### 6.2 配置合并

LDD 适配器先读取算法默认配置，再读取任务关联的超参数模板配置；模板中的同名参数覆盖算法默认值。数据集路径默认来自任务的数据集资源，也可以由超参数中的 `data_path` 显式指定。

当前 LDD 可映射的关键参数包括：

```text
dataset, trigger_type, trigger_label, poisoned_mode,
poisoned_portion, batch_size, num_epochs, lr_poison,
r, alpha1, alpha2, seed
```

平台对未在 LDD 白名单中的参数进行拒绝，避免无效配置静默进入算法脚本。

### 6.3 对原始算法代码的隔离

VaB 的原始研究脚本在模块加载时执行，并包含固定实验矩阵、共享相对目录和交互式绘图调用。平台不直接修改 `LDD.py`，而是使用 Python AST 将其转换为一次任务对应的临时脚本：

1. 将固定数据集、触发器和中毒比例替换为平台传入配置。
2. 将批次大小等受控参数替换为有效配置。
3. 将输出路径重定向到当前任务的专属目录。
4. 保存每个隔离比例对应的样本索引文件。
5. 关闭交互式 Matplotlib 展示调用。

这种方式保留原始研究代码，降低后续论文对比、算法更新和平台集成之间相互影响的风险。

### 6.4 结果协议

Python 适配器将结果写为 JSON，后端保存到训练前任务的 `cleaning_result` 字段。结果至少包含：

```json
{
  "executor": "python-process",
  "stage": "pre_defense",
  "status": "success",
  "message": "任务执行完成",
  "started_at": "ISO-8601 时间",
  "finished_at": "ISO-8601 时间",
  "effective_config": {},
  "metrics": {},
  "artifacts": {}
}
```

失败结果还包含 `error_code` 与 `failure_reason`。LDD 的 `metrics` 中可包含按隔离比例统计的干净子集纯度和选中样本数量；其中纯度依赖 VaB 实验中已知的中毒样本索引，只适用于受控实验评估，不能表述为未知生产数据的通用标签指标。

## 8. 已完成与待完成

### 已完成

- 安全训练工作台及训练前任务管理页面。
- 数据集、模型、算法、超参数模板等基础资源管理。
- 训练前任务校验、启动、状态查询和结构化结果保存。
- Mock 执行器，用于验证未接入真实算法时的平台流程。
- Python 本地进程执行器和 LDD VaB 适配器。
- LDD 配置映射、任务隔离、结果产物收集和一次工程运行验证。
- LDD 任务详情可视化，包括纯度进度条、配置标签、产物列表和 PNG 安全预览。

### 待完成

- 根据论文实验计划固化 LDD 的数据集、攻击方式、轮数和评估指标，并完成正式实验。
- 接入其他训练前、训练中和可选训练后算法，复用统一执行器和结果协议。
- 支持清洗后数据集、模型权重和实验报告的受控下载。
- 增加任务队列、取消、失败重试、异步执行和资源占用管理。
- 增加参数 schema 的后端校验、参数快照和实验可追溯信息。
- 完善清洗率、攻击成功率、模型精度保持率等论文指标与报告。
- 在安全训练领域边界稳定后，迁移至 Spring Boot 3 与 Vue 3 技术栈。

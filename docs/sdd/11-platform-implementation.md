# 当前平台实现说明

更新时间：2026-10-26

## 1. 文档目的

本文档记录“面向数据清洗的安全模型训练系统”当前已落地的平台实现，用于指导后续功能迭代、论文系统说明和答辩演示准备。

本文档描述的是当前工程版本的实际能力，不将规划中的功能、后续拟接入算法或工程验证结果表述为已完成的论文实验结论。

## 2. 平台定位与范围

平台从早期网络安全竞赛项目重构而来，当前重点是为图像训练数据的训练前防御提供可视化管理、任务编排、算法调用和结果展示能力。

当前平台负责：

- 管理数据集、模型、算法和超参数模板等实验资源。
- 创建、校验、启动和查询训练前防御任务。
- 通过统一执行器调用外部 Python 算法。
- 将算法过程和结构化结果保存至任务记录，并在前端展示。
- 对任务产物中的 PNG 图像提供受限预览、可视化实验报告和清洗子集异步导出下载。
- 记录任务命令和清洗子集导出的操作审计，支持按任务查看操作人、动作和状态变化。
- 以演示空壳方式呈现训练前、训练中、训练后三大防御阶段及其算法目录，便于答辩和成果展示。

当前真实接入范围仅包含 LDD 训练前防御算法。训练中防御、训练后防御和其他训练前对比算法
在前端以展示占位方式呈现完整菜单、阶段页和算法卡片，不创建真实任务、不调用 Python 执行器。

## 3. 当前技术实现

### 3.1 实际运行基座

当前运行版本采用以下稳定技术栈：

| 层次 | 当前实现 |
| --- | --- |
| 前端 | Vue 3、Vite、Element Plus、Pinia、Vue Router 4 |
| 后端 | Java 17、Spring Boot 3.5、Spring Security 6、JWT、MyBatis-Plus |
| 数据与状态 | MySQL 作为事实源；Redis 缓存资源目录；消息队列尚未接入 |
| 算法运行时 | Python、PyTorch、外部 VaB 算法工程 |
| 构建工具 | Maven、npm |

旧版 ELADMIN 工程保留在仓库中作为回退基线，迁移版不依赖旧后端业务控制器。

### 3.2 工程模块

```text
security_model
├── migration-backend/               Spring Boot 3 / Java 17 后端
├── migration-frontend/              Vue 3 / Vite 前端
├── algorithm-runtime/vab/           VaB 外部算法适配器
├── eladmin/                         旧后端回退基线
├── eladmin-web/                     旧前端回退基线
├── docs/sdd/                        SDD 设计与运行文档
└── sql/                             数据库初始化和演示数据脚本
```

### 3.3 演示页面结构

登录页使用后端验证码和 JWT 认证，不提供绕过后端认证的演示登录入口。资源目录、任务、报告、
日志和审计页面以接口返回为准，接口失败时展示明确错误状态。

| 页面 | 路径 | 说明 |
| --- | --- | --- |
| 工作台 | `/dashboard` | 展示平台定位、迁移状态和当前真实算法范围 |
| 数据集资源 | `/datasets` | 数据集列表，以及写入 MySQL 的新增/编辑/停用表单 |
| 算法资源 | `/algorithms` | 三大防御阶段算法目录，以及写入 MySQL 的新增/编辑/停用表单 |
| LDD 清洗任务 | `/tasks` | 当前真实 LDD 任务中心 |
| 训练前防御 | `/defense/pre` | LDD、Spectral Signature、Activation Clustering |
| 训练中防御 | `/defense/during` | 鲁棒训练、梯度防护、训练过程监测占位 |
| 训练后防御 | `/defense/post` | 触发器反演、模型修复、安全评估占位 |
| 接口扩展预览 | `/training-defense` | 统一执行器和后续算法接口说明 |

外部算法代码、数据集、模型检查点和真实任务输出不复制到平台仓库，仍由外部 VaB 项目维护。平台只维护适配器、资源引用、请求协议和结果展示。

资源目录查询优先从 Redis 读取，缓存未命中时回源 MySQL 并写入 5 分钟 TTL。Redis 连接不可用时
自动降级为 MySQL 查询；新增、编辑和停用资源会清理相关列表和实体缓存，不影响任务状态和报告查询。

## 4. 业务对象

| 对象 | 业务含义 | 当前用途 |
| --- | --- | --- |
| 数据集 | 训练或清洗任务所使用的数据目录及说明 | 为算法提供本地数据集根目录 |
| 模型 | 任务关联的模型资源 | 训练前任务可登记模型信息；LDD 当前主要使用 VaB 内部模型流程 |
| 算法 | 可调用的防御算法及其实现路径、默认配置和参数 schema | 当前真实路径为 `vab://pre-defense/ldd` |
| 超参数模板 | 可复用的算法配置 JSON | 覆盖算法默认配置，形成单次任务有效配置 |
| 训练前防御任务 | 一次数据风险检测和干净子集选择任务 | 记录状态、进度、输入快照和清洗结果 |
| 任务产物 | 日志、结果 JSON、索引文件、模型检查点和图像等 | 保存在任务专属外部目录，前端按任务结果展示 |

## 5. 主要业务流程

### 5.1 资源配置与任务创建

```text
管理员登录平台
  -> 登记数据集、算法、超参数模板和模型资源
  -> 创建训练前防御任务
  -> 关联数据集、LDD 算法和超参数模板
  -> 保存为 pending 状态
```

任务启动前，后端校验数据集、算法阶段和超参数模板是否存在且匹配。校验通过后，平台生成不可变的执行请求快照，而不是让算法运行时反复查询业务表。

### 5.2 任务操作审计

任务创建、编辑、启动、失败重试、取消和删除，以及清洗子集导出提交和导出重试，均写入独立的
`security_operation_audit` 表。审计记录保存资源类型、资源 ID、动作、当前 JWT 用户名、前后状态、
请求快照、结果说明和创建时间。

任务命令与审计写入处于同一 Spring 事务中，业务命令回滚时不会留下孤立的审计记录。清洗子集导出
通过导出任务 ID 与主任务关联，查询任务审计时合并展示两类操作。

当前 LDD 任务还会对算法默认配置、超参数模板和任务自定义参数进行 JSON 对象校验，
并按 LDD 白名单检查必填项、数据类型、整数约束和数值范围。非法参数在进入异步执行器
之前被拒绝，避免任务已经进入运行态后才暴露配置错误。

### 5.2 训练前任务执行

```text
前端任务页
  -> POST /api/pre-defense/start/{taskId}
  -> PreDefenseService
  -> DefenseTaskExecutor
  -> PythonDefenseTaskExecutor
  -> algorithm-runtime/vab/algorithm_entry.py
  -> 外部 VaB LDD 运行环境
  -> 任务专属结果目录
  -> MySQL cleaning_result
  -> 前端任务详情页
```

任务状态当前使用 `pending -> running -> success/failed/canceled`。任务启动前还会经过单机执行配额准入：
系统限制运行中 LDD 任务总数、单用户运行任务数，并检查有界执行池是否仍接收任务。准入成功后，
这些限制和当时的运行任务数量会写入当前尝试的快照，便于报告解释任务为什么进入等待或失败。
当前配额是 JVM 内单机策略，不宣称提供跨机器或操作系统级 CPU、内存、GPU 硬隔离；后续迁移到
独立 worker 或容器时再替换为分布式租约和资源调度。

任务领取通过数据库条件更新完成，
只有一个请求可以把同一任务从 `pending` 原子领取为 `running`。每次启动生成新的 UUID
`run_id` 和递增 `attempt`，进度、结果和结束回调必须匹配当前运行标识，旧运行或超时
运行的迟到回调会被数据库条件更新自动忽略。

执行失败时，执行器将错误码、失败原因、任务专属产物目录以及 stdout/stderr 日志路径写入
结果 JSON，供前端在任务详情中定位执行现场。失败任务可以重试：平台只允许 `failed ->
pending` 的受控状态回退，并清除旧运行结果后生成一条新的执行参数快照和独立执行目录。
任务领取提交事务成功后，才派发外部 Python 执行器，避免数据库回滚但算法进程已经启动。
运行中的任务可以取消：平台先按当前 `run_id` 原子写入 `canceled` 终态，事务提交后再
回收对应 Python 进程。因进度、结果和结束回调均要求任务仍处于 `running` 且 `run_id`
一致，取消后的迟到回调会被安全丢弃。

当前业务规则：新后端只允许实现路径为 `vab://pre-defense/ldd` 的训练前算法启动，非 LDD 算法请求会被拒绝。

### 5.3 结果查看与可视化

任务完成后，前端任务详情页从训练前任务的 `cleaning_result` 中读取结构化结果，并展示：

- 算法名称、运行时长和实验配置标签。
- 不同隔离比例下的干净子集纯度和保留样本数量。
- 任务输出目录、日志路径、选中样本索引文件和其他产物。
- 每次启动或重试冻结的资源与参数快照，以及完整清洗结果 JSON。
- 任务产物中的 PNG 图像预览。
- 可视化实验报告，包含任务概览、执行尝试、冻结参数和 LDD 指标。
- 成功 LDD CIFAR-10 任务按隔离比例提交导出任务，查询进度并下载清洗后的数据子集。

图像预览通过 `GET /api/pre-defense/artifact-preview/{taskId}` 提供。后端会先读取任务结果中的产物根目录，只允许访问该目录下存在的 PNG 文件，防止通过前端参数读取任意本地文件。

清洗数据集导出通过以下接口完成：

```text
POST /api/pre-defense/cleaned-dataset/exports/{taskId}
GET  /api/pre-defense/cleaned-dataset/exports/{exportId}
GET  /api/pre-defense/cleaned-dataset/exports/{exportId}/download
```

后端使用 `(task_id, isolation_ratio)` 唯一约束避免重复提交同一导出任务。导出任务自身使用
`pending -> running -> success/failed` 状态，记录进度、产物、元数据和失败原因。当前迁移版
没有导出任务启动恢复扫描：应用重启后遗留的导出 `running` 或 `pending` 记录不会由启动逻辑自动
收敛或重新派发。旧的
`GET /api/pre-defense/download-cleaned-dataset/{taskId}` 同步接口保留用于兼容。

导出过程不会直接下载索引文件：后端根据 LDD 产物中的 `selected_indices_<ratio>.npy`
重建对应的原始 CIFAR-10 训练样本，并生成包含图片、标签、索引和元数据的 ZIP。

任务详情页会在任务处于 `running` 状态时轮询任务当前 `run_id` 对应执行目录中的 `stdout.log` 和
`stderr.log`，并将上一次返回的文件 offset 传回后端。后端按 offset 读取单次最多 256 KB 的新增内容，
同时对真实目录和文件名执行 containment 校验，只返回任务自身的日志内容。相同接口还返回适配器写入的
`progress.json` 快照，包含当前阶段、阶段说明、进度百分比、当前 epoch、总 epoch、提示消息和最近心跳时间。
Java 执行器在 Python 进程运行期间读取该快照并更新 MySQL 的任务百分比，因此前端不会等到 Python
整体退出后才看到进度。前端对超过 60 秒未变化的心跳只提示“较久未更新”，不直接判定任务卡死；
任务是否成功仍以结构化 `result.json` 和数据库终态为准。后续可按答辩演示需要升级为 SSE/WebSocket
日志流。

## 6. LDD 接入实现思路

### 6.1 统一执行器边界

后端业务层通过 `DefenseTaskExecutor` 调用算法。执行器接收 `DefenseTaskRequest` 快照，其中包含任务、数据集、算法、超参数模板和可选模型资源。

这样做的目的如下：

- Controller 和 CRUD Service 不依赖具体的 PyTorch 或 VaB 实现。
- 后续算法只需遵守相同请求与结果协议，无须重写任务管理页面。
- 任务启动时的资源与配置可被记录，便于后续实验复现。

### 6.2 配置合并

LDD 的有效配置按照以下固定顺序合并：

```text
算法默认配置 -> 超参数模板配置 -> 任务自定义参数
```

后加载的同名参数覆盖前面的值。后端和 Python 适配器使用相同的合并顺序，并在后端
启动任务前执行参数白名单、必填项、类型和范围校验。数据集路径默认来自任务的数据集
资源，也可以由超参数中的 `data_path` 显式指定。

当前 LDD 可映射的关键参数包括：

```text
dataset, trigger_type, trigger_label, poisoned_mode,
poisoned_portion, batch_size, num_epochs, lr_poison,
r, alpha1, alpha2, seed
```

平台对未在 LDD 白名单中的参数进行拒绝，避免无效配置静默进入算法脚本。

### 6.3 对原始算法代码的隔离

VaB 的原始研究脚本在模块加载时执行，并包含固定实验矩阵、共享相对目录和交互式绘图调用。平台不直接修改 `LDD.py`，而是使用 Python AST 将其转换为一次任务对应的临时脚本：

1. 将固定数据集、触发器和中毒比例替换为平台传入配置。
2. 将批次大小等受控参数替换为有效配置。
3. 将输出路径重定向到当前任务的专属目录。
4. 保存每个隔离比例对应的样本索引文件。
5. 关闭交互式 Matplotlib 展示调用。

这种方式保留原始研究代码，降低后续论文对比、算法更新和平台集成之间相互影响的风险。

### 6.4 结果协议

Python 适配器将结果写为 JSON，后端保存到训练前任务的 `cleaning_result` 字段。结果至少包含：

```json
{
  "executor": "python-process",
  "stage": "pre_defense",
  "status": "success",
  "message": "任务执行完成",
  "started_at": "ISO-8601 时间",
  "finished_at": "ISO-8601 时间",
  "effective_config": {},
  "metrics": {},
  "artifacts": {}
}
```

失败结果还包含 `error_code` 与 `failure_reason`。LDD 的 `metrics` 中可包含按隔离比例统计的干净子集纯度和选中样本数量；其中纯度依赖 VaB 实验中已知的中毒样本索引，只适用于受控实验评估，不能表述为未知生产数据的通用标签指标。

### 6.5 可复现快照与资源生命周期

任务启动时会把本次尝试的请求、运行环境和资源指纹写入 `execution_snapshot`。快照当前包含：

- Java 版本、厂商、操作系统、CPU 并行度和时区；
- Python 解释器、适配器脚本、执行工作目录和摘要策略；
- 数据集、算法和超参数资源的 ID、名称、路径、真实路径、大小、修改时间和身份摘要；
- 对可访问且未超过大小上限的数据集文件计算 SHA-256 内容摘要。

内容摘要不会复制数据集到数据库，默认只记录摘要和元数据；对于超过上限的文件，快照会明确记录
`skipped_size_limit`，而不是伪装成已经完成完整校验。内容摘要策略可通过环境变量关闭或调整大小上限。

算法进程完成后，结果 JSON 还会记录实际运行时信息，包括适配器版本、Python 版本与解释器路径、
PyTorch/NumPy 版本、CUDA 版本、CUDA 可用性、设备数量和 GPU 型号。这样报告既能展示启动前冻结的
配置快照，也能展示外部 Python 进程实际使用的机器学习运行环境。

资源删除由服务层检查任务引用数量。只要数据集、算法或超参数模板仍被历史任务引用，就拒绝删除，
保证报告关联、重试快照和清洗子集导出所依赖的资源不会被管理操作破坏。

- 历史 Mock 执行器与免认证演示入口不属于迁移版当前运行链路；三大防御阶段中的非 LDD 算法卡片为静态展示内容，不创建真实任务。

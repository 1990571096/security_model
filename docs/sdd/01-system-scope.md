# 系统范围说明

更新时间：2026-11-13（R0 事实校准；R1 归属隔离落地）

## 目标系统

系统重构目标是将当前比赛项目改造为“面向数据清洗的安全模型训练系统”。系统以图像训练数据的后门中毒风险检测与清洗为核心，当前**真实执行**只开放 LDD 训练前数据清洗；其他训练前对比算法、训练中防御、训练后防御是展示页面，不创建真实任务、不产生真实指标。

交付形态：**单机真实运行、多个登录用户分别管理并查看自己的实验**。数据集与产物保存在受控本地目录，开发机资源预算为 RTX 2060 6GB 显存 / 16GB 内存。分布式执行（独立 Worker、多实例）只是可选扩展，不作为交付门槛。

> 状态说明：多用户归属隔离与共享资源管理员权限**已在 R1 落地**（任务以 `owner_user_id` 授权），细节见 [18-multiuser-ownership-and-resources.md](18-multiuser-ownership-and-resources.md) §7。GPU 单槽租约、导出恢复仍未实现，不要把 R2 规划写成已有能力。

## 用户与边界

| 角色 | 目标能力 | 当前实现 |
| --- | --- | --- |
| 管理员 | 维护共享数据集/算法/超参数；显式授权后跨用户查看；操作留审计 | R1 已实现资源写权限；跨用户读由 `security-model.ownership.admin-cross-user-read` 控制，默认关闭 |
| 实验用户 | 创建、启动、重试、取消、查看自己的任务、报告、日志、产物与导出 | R1 已实现：任务写操作要求 owner，读操作按 owner 过滤 |
| 只读观察者 | 查看被授权范围内的实验，不可写 | 未实现（当前没有第三种角色） |

认证现状：登录走验证码 + JWT（`/auth/code`、`/auth/login`），JWT 密钥必须由 `SECURITY_MODEL_JWT_SECRET` 提供且不少于 32 字节，否则后端拒绝启动。JWT 携带 `userId` 与 `adm`，但**授权以数据库为准**：每个请求按 `userId` 回查 `sys_user.enabled` 与 `is_admin`，禁用账号、删除账号或撤销管理员后旧令牌立即失效；令牌里的 `adm` 只作签发记录，不参与权限判定。`owner_user_id` 是唯一授权依据。升级前签发的旧 token 没有 `userId`，需重新登录后才能执行任务写操作。

## 核心流程（按实际实现描述）

1. **数据集登记与验证**：登记已有本地目录的元信息（名称、类型、路径、样本数、说明），不提供文件上传。登记后 `parse_status='pending'`；管理员调用 `POST /api/dataset/{id}/validate` 校验路径存在、可读、非空后置为 `success`，任务才能使用。验证失败写 `failed` 与原因，不抛异常。
2. **算法与超参数**：登记 LDD 算法（`vab://pre-defense/ldd`）与超参数模板，按“算法默认配置 → 超参数模板 → 任务自定义参数”合并，并按 LDD 白名单校验。
3. **训练前任务**：创建任务（`pending`）→ 启动时原子领取为 `running`（生成 `run_id` 与递增 `attempt`，写入不可变执行快照）→ 事务提交后由有界 JVM 线程池派发 Python 进程。
4. **算法执行**：Python 适配器调用外部 VaB 工程，生成单任务脚本，写出 `progress.json`、`result.json`、日志、`selected_indices_<ratio>.npy`、模型检查点与图像。
5. **结果与观测**：Java 轮询 `progress.json` 更新 MySQL 百分比；前端轮询日志接口读取增量 stdout/stderr 与进度快照；任务终态以 `result.json` 与数据库状态为准。
6. **报告**：从任务行、资源行、执行快照与结果 JSON 组装报告，展示参数、指标、产物与本次实际 Python/CUDA/GPU 运行环境。
7. **导出**：对成功且含保留索引的 CIFAR-10 任务，按隔离比例异步重建清洗子集 ZIP 并下载。

## 当前优先级

- P0：多用户归属与授权（R1）、任务/导出可靠性（R2）、持久调度与幂等（R3）。
- P0 的平台基础已具备：LDD 真实任务链路、执行快照、进度与日志、报告、异步导出、操作审计、资源目录缓存。
- P1：可观测性与部署复现（R5）。
- P2：RAG 检索（R6）、只读实验 Agent（R7）。
- 可选：RabbitMQ + 独立 Worker（R4）、多实例/GPU Worker 压测（R8）。

## 非目标范围

以下能力不属于当前交付主线，**不实现、不在文档中声称已具备**：

- 训练中防御、训练后防御与其他训练前对比算法的真实执行（仅保留展示页面与算法目录）。
- 模型训练闭环（清洗后数据集到安全模型训练的衔接仍是后续项）。
- RabbitMQ/Kafka、独立 Worker、Kubernetes、多实例调度（仅可选设计；当前未接入）。
- RAG 知识库与 Agent 写操作（R6/R7 尚未开始；Agent 只能使用外部大模型 API，本机不部署模型）。
- 对象存储/S3、支付、邮件、代码生成器、远程部署与服务器管理（原 ELADMIN 遗留模块，不进入主流程）。
- 分布式训练、多 GPU 调度（单机单卡，分布式仅为学习扩展）。

## 论文目标映射

- 数据登记模块：`sys_dataset`（本地路径元数据）。
- 算法登记模块：`sys_algorithm`、`sys_hyper`。
- 数据清洗模块：`sys_pre_defense` + `PythonLddTaskExecutor` + `algorithm-runtime/vab/algorithm_entry.py`。
- 报告模块：`PreDefenseReportQueryService`（结果 JSON 承载，暂不新增独立报告表）。
- 安全模型训练模块：未实现。
- 评估指标（清洗率、攻击成功率、干净准确率、性能保持率）：尚未系统化定义，工程验证结果不得替代论文指标。

## 事实来源与优先级

发生文档与代码冲突时，**以运行代码 + SQL + 已执行测试为事实**，先修正文档再谈实现（本期修正清单见 [05-decisions.md](05-decisions.md) 的 ADR-012）。已知且已修正的冲突：

| 冲突 | 旧表述 | 实际 |
| --- | --- | --- |
| 数据导入 | “上传、解析、状态管理” | 仅本地路径元信息登记；无上传；`parse_status` 无推进入口 |
| `result.json` 缺失 | “可补最小成功结果” | 抛出 `RESULT_MISSING`，任务失败 |
| Python 执行器 profile | `--spring.profiles.active=dev,python-executor` | 该 profile 只存在于旧 `eladmin`；迁移版用配置键/环境变量 |
| 接口清单 | `/api/tasks`、`/api/reports/{id}`、`/api/datasets/upload` 等 | 均不存在，实际接口见 03 |
| 首页与样例数据 | “接口失败显示明确错误状态，不使用样例数据” | 工作台、案例页、运行监控页为硬编码演示数据 |

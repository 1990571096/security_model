# 项目目标与阶段进度说明

更新时间：2026-07-24

## 1. 项目整体目标

本项目由早期网络安全竞赛项目重构而来，论文系统名称为“面向数据清洗的安全模型训练系统”。

系统面向图像训练数据的后门中毒与异常样本风险，围绕“数据导入、风险检测、数据清洗、安全训练、效果评估、报告生成”形成可视化闭环。平台的职责是统一管理数据集、模型、算法、参数、任务状态、执行结果和实验报告；具体安全算法通过独立执行器接入，避免算法实现与业务管理代码耦合。

当前研究与实现重点是训练前数据清洗。后续将接入两个训练前防御算法、一个训练中防御算法，并根据实验需求扩展训练后评估或防御能力。

## 2. 建设原则

- 采用 SDD 文档驱动迭代，先明确边界、接口和验收标准，再实施代码改动。
- 优先形成可运行、可展示、可验证的最小闭环，真实算法以可替换执行器方式接入。
- 当前先复用原项目基础设施，后续逐步迁移到 Spring Boot 3、Java 17、Vue 3、Vite 和 Element Plus。
- 在领域模型和任务协议稳定前，不同时进行大规模框架升级与业务重构。

## 3. 目标业务闭环

```text
数据集导入
  -> 数据集解析与状态管理
  -> 算法和超参数选择
  -> 训练前风险检测与数据清洗
  -> 安全训练或训练中防御
  -> 训练曲线与评估指标展示
  -> 防御报告与结果产物下载
```

## 4. 当前实现进度

当前阶段已完成“可视化管理界面 + 基础资源管理 + mock 任务执行 + 结果展示”的 MVP 闭环。系统可以创建训练前、训练中防御任务，启动任务后推进状态，并将结构化结果返回前端展示。

当前运行基座仍为 Spring Boot 2.7 + Vue 2。它是用于稳定主流程和验证业务边界的过渡版本，不是最终技术栈。

### 4.2 当前可演示能力

- 登录后进入安全训练工作台。
- 管理数据集、模型、算法和超参数模板。
- 使用内置 baseline 创建并启动训练前防御任务。
- 查看任务进度、清洗统计和结构化清洗结果。
- 创建并启动训练中防御任务。
- 查看训练轮数、最终精度、损失曲线和精度曲线。
- 通过接口文档验证任务、进度和结果查询接口。

### 4.3 当前仅为 MVP 占位的能力

- 内置 baseline 算法当前由 `MockDefenseTaskExecutor` 模拟，不读取真实数据文件，也不执行真实 PyTorch 训练。
- mock 任务不会生成真实清洗后数据集、模型权重或可下载 artifact。
- LDD 已于 2026-08-19 完成一次 CIFAR-10 / SIG / batch size 128 / 5 epoch 的工程验证运行；该结果不能替代论文正式实验结论。
- 训练后防御仍处于扩展预留状态，未纳入当前主流程。

## 5. 待完成工作

### P0：真实算法与实验闭环

1. 完善 LDD 训练前防御的实验运行闭环。
   - 由论文实验计划确定数据集、训练轮次、攻击方式和各算法配置。
   - 以固定配置执行 LDD，并记录可复现实验参数、结果和产物。
   - 在各算法的输出语义确认后，补齐真实清洗数据集、风险评分和下载能力。

2. 接入第二个训练前防御算法项目。
   - 在不改变平台任务协议的前提下完成第二种算法接入。
   - 对比两种算法的参数、清洗比例、子集纯度、运行时间和防御效果。

3. 接入训练中防御算法项目。
   - 使用统一输入模型、训练数据集和参数配置。
   - 输出真实训练日志、损失曲线、精度曲线和模型产物。

4. 建立真实数据与模型产物管理。
   - 统一数据集、清洗数据集、模型权重和日志目录的存储路径。
   - 支持任务结果下载、输出模型下载和结果可追溯。

### P1：任务与评估能力完善

1. 抽取统一任务生命周期，补充 `queued`、`canceled`、失败重试和取消能力。
2. 建立异步任务机制，避免长时间算法执行占用 Web 请求线程。
3. 增加参数 schema 后端校验、参数快照和任务可复现实验记录。
4. 新增训练任务或重构训练中任务，使“清洗后数据 -> 安全模型训练 -> 评估”链路更加清晰。
5. 新增防御报告模块，汇总数据清洗、算法参数、训练曲线、模型指标和结论。
6. 补充后门攻击成功率、清洗率、子集纯度、防御性能保持率等论文实验指标。

### P2：工程重构与技术栈升级

1. 按菜单、接口、前端页面和 Maven 依赖顺序裁剪支付、邮件、S3、远程部署、数据库执行器和代码生成等无关模块。
2. 将后端升级到 Java 17 + Spring Boot 3 + Spring Security 6，并完成 `javax.*` 到 `jakarta.*` 迁移。
3. 将前端升级到 Vue 3 + Vite + Element Plus + Pinia。
4. 将安全训练领域逐步迁移到独立的 `securitymodel` 领域包，降低对 ELADMIN 结构的依赖。

### P3：质量与部署

1. 为任务校验、执行器结果协议和关键接口补充自动化测试。
2. 为前后端建立持续集成构建与基础检查。
3. 完善运行配置示例，分离本地密码、路径和环境变量。
4. 补充部署文档、演示数据说明和论文复现实验指南。

## 6. 下一阶段建议

下一阶段优先继续完善平台能力，而不是立即大规模升级 Spring Boot 3 或 Vue 3。LDD 已经完成接入和工程运行验证，当前应先完善任务生命周期、参数快照、产物管理、报告结构和前端结果展示；待论文实验配置确定后，再在稳定的平台协议上执行正式实验。

真实算法项目到位后，需要优先确认以下信息：

- 算法代码的 Python 版本、依赖清单和 GPU/CPU 要求。
- 输入数据集目录结构、标签文件格式和预处理要求。
- 可配置参数、默认值、参数范围和结果指标定义。
- 输出清洗数据、模型、日志、图表和报告文件的目录结构。
- 单次任务的预计运行时间、失败场景和可取消策略。

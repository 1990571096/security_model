# 项目讲解与演示

先记住三个画面。用户保存一条待启动的任务，后台接手一次有编号的运行，用户拿到报告与可下载的子集。讲完这三个画面，面试官就能理解你接下来要讲的技术在解决什么问题。用 `42 / r1 / 1` 走一遍页面和代码。[业务流程时序图](project-business-flows.md#一次-cifar-10-实验怎样完成)

## 30 秒版本

> 这是一个面向深度神经网络后门防御实验的单机平台。我接入了训练前 LDD：用户选择数据集和算法、创建任务、确认启动，Java 调度 Python/VaB 执行数据清洗，页面查看进度、日志、报告，并按需导出清洗子集。工程上重点讲三件事：Java 与 Python 的文件协议、长任务在失败/取消/重启下的状态一致性，以及 `db` 与 `rabbit` 两种派发模式怎样共享同一套任务事实。

如果面试官只给 30 秒，最后一句可以换成“我还做过 Redis 缓存失效和 RabbitMQ 重复消费的收敛”。

## 90 秒口述

> 平台默认是单机 `db` 模式。用户在页面选好数据集、LDD 和参数，创建接口只写一条 `pending` 任务，不启动训练。用户核对后点启动，后端用 `SELECT FOR UPDATE` 锁任务行，检查归属和状态，分配 `runId` 和 `attempt`，写执行快照、派发意图，并在事务内把任务改成 `running`。事务提交后才把请求送进本地线程池。
>
> 执行器把本轮请求写成 `request.json`，用 `ProcessBuilder` 启动 Python 适配器；Python 解析后生成任务脚本，再启动 VaB 训练。训练期间写 `progress.json`，结束后写 `result.json`。Java 校验 `stage、run_id、attempt、status、artifacts`，再用带 `current_run_id` 和 `status='running'` 的 SQL 更新终态。旧轮结果晚到会影响 0 行。
>
> 实验成功后，报告服务整理本轮结果和产物。以 CIFAR-10 为例，用户选一个已有筛选索引的比例，平台再异步生成 ZIP。我的后端讲解会重点展开跨语言协议和状态一致性。比如两次启动请求如何相互隔离，或者第一轮进程迟到时，数据库如何保护第二轮的结果。

## 三分钟白板

先画默认 `db` 路线：

```text
Vue
 │ POST /api/pre-defense
 ▼
Spring Boot ──INSERT──> MySQL(pending)
 │
 │ 用户确认 POST /start
 ▼
事务: FOR UPDATE → runId/attempt → 申请租约 → 写快照、running 与 intent
 │ COMMIT
 ▼
afterCommit → taskAsync 线程池
 │
 ▼
Java 执行器 ──request.json──> Python 适配器 ──> VaB
 │                                  │
 │<──── progress.json / result.json ┘
 ▼
条件 UPDATE MySQL(success/failed)
 │
 ▼
报告与日志 → 选择保留比例 → 导出记录 → ZIP
```

然后补 Rabbit 分支：

```text
启动事务 ──同一事务──> Outbox
                         │
                      Relay
                         │ publish + confirm
                      RabbitMQ
                         │ manual ACK
                      Worker
                         │
                      Python/VaB
```

白板讲解节奏：

| 时间 | 画什么 | 讲什么 |
| --- | --- | --- |
| 0:00–0:40 | 用户目标与四类资源 | 数据、算法、参数、产物 |
| 0:40–1:30 | 创建与启动两个请求 | 为什么创建不执行，runId 何时产生 |
| 1:30–2:10 | Java/Python 文件协议 | 为什么不用 stdout 当结果 |
| 2:10–2:40 | 旧结果晚到 | `r1` 对 `r2`，SQL 0 行 |
| 2:40–3:00 | Redis/MQ 位置 | 缓存不是事实，MQ 可能重复 |

## 一分钟页面走查

白板讲完调度后，用页面证明“设计不是纸面架构”：

1. **数据集资源**：类型显示 `image/text/table`，状态只有已核验/待验证；停用在名称旁。强调这是展示压缩，不是改后端类型。Tiny 显示已核验但创建任务会被拒绝。
2. **安全防御任务**：页面只保留任务统计和任务列表；执行池、接入范围不在这里，避免业务与运行监控重复。
3. **运行监控**：本机 CPU/内存/JVM/磁盘在前，执行资源、平台接入、消息派发在后。演示时读出接口返回的实际 `mode`、`role` 和消费者状态。
4. **数据统计**：4 个 KPI、五状态环、7/14/30 日趋势、质量环、阶段构成、最近明细和统计口径。告诉面试官哪些指标没有真实采集源，所以不展示。

这一分钟的核心不是“页面好看”，而是：

```text
业务操作 → 任务页
运行状态 → 运行监控
历史分析 → 数据统计
资源维护 → 数据集/算法页
```

## 现场演示

| 顺序 | 展示什么 | 一句话解释 |
| --- | --- | --- |
| 1 | 数据集页四条真实数据 | CIFAR/GTSRB 校验通过；类型短名、状态二态；Tiny 只登记不执行 |
| 2 | 任务页 | 只保留任务统计和列表，执行池/接入范围已移到运行监控 |
| 3 | 算法详情参数配置中心 | 算法默认配置是唯一来源，无独立模板 |
| 4 | 创建任务与 Network | 创建只返回 `pending`，启动是第二个请求 |
| 5 | 任务详情与 attempt 目录 | `request.json` 串起本轮身份 |
| 6 | 日志/报告 | 日志按 offset 增量读，报告来自结构化结果 |
| 7 | 运行监控 | 本机指标在前；“执行资源 / 平台接入 / 消息派发”分组在后 |
| 8 | 数据统计 | 状态环、7/14/30 趋势、质量环、阶段构成和统计口径 |

## 讲清自己的贡献

按四句话准备一个真实改动：

1. 用户遇到什么问题；
2. 改了哪个类、哪个行为；
3. 用什么测试/日志验证；
4. 边界是什么。

示例一：数据集接入。

> 原来数据集验证只认 CIFAR 目录，GTSRB 的 HDF5 和 Tiny ImageNet 只能算“路径存在”。我补了格式识别：CIFAR 走官方 MD5，GTSRB 校验 HDF5 文件头并把父目录作为 VaB 运行根，Tiny 校验目录但在创建任务时明确拒绝。验证时用四条真实路径逐条调用验证接口，并检查参数预览分别得到 `cifar10/cifar100/gtsrb`。

示例二：缓存一致性。

> 资源列表原来直接查 MySQL。我加了 Redis read-through，但资源修改后如果普通删除，慢读者可能把旧值写回。我用 generation + Lua 条件写解决这个竞态；执行契约仍然查 MySQL 权威行。Redis 故障只降级，不影响任务正确性。

示例三：MQ 重复消费。

> Rabbit 模式里，消息重复是正常事件。我用 `messageId` 消费账本先插入 `processing`，重复投递根据 claim 状态决定 ACK、延迟重投还是抢占；任务层再用 `runId/attempt` 校验。验证覆盖 Broker 重投、Worker 崩溃和旧轮晚到。

示例四：页面职责重组与统计可视化。

> 用户反馈三个问题：数据集类型 `image_classification` 太长、验证状态混了停用；任务页和执行池/接入范围混在一起；数据统计和工作台重复。我按页面职责拆开：数据集页只显示短类型和“已核验/待验证”，停用放名称旁；任务页只保留任务操作，执行资源和接入信息并入运行监控；统计页改成图表化分析，接入 7/14/30 日趋势、质量环和明细。验证时构建前端并逐页在浏览器检查，发现 KPI 选择器被 `el-card__body` 破坏、窄屏单选竖排，最后用显式类名和 `el-select` 修复。

## 演示边界

| 不要说 | 应该说 |
| --- | --- |
| 平台默认使用 RabbitMQ | 仓库默认 `db/api`，实例是否切换以运行时接口为准 |
| Outbox 为 0 说明消息队列正常 | `db` 模式不写 Outbox，0 只是该模式的正常结果 |
| 已核验等于可执行 | 已核验是文件/统计通过；Tiny 可核验但当前 LDD 不支持 |
| 数据统计都是实验结论 | 没有采集源的 ASR、GPU 利用率等不展示 |
| RabbitMQ 保证只执行一次 | 至少一次投递，靠账本和任务身份收敛重复 |
| 单机双进程演练等于生产部署 | 只证明单机可靠性；“生产多机”未验收 |

## 面试官可能追问的转场

| 追问 | 转到哪 |
| --- | --- |
| “为什么不用同步接口？” | 长训练、HTTP 超时、进程生命周期 |
| “为什么不用 Java 锁？” | 多 JVM/重启后事实在 MySQL |
| “MQ 能保证只执行一次吗？” | 不能，讲消费账本和幂等收敛 |
| “Redis 挂了怎么办？” | 回源 MySQL，缓存不阻塞 |
| “Python 挂了怎么知道？” | 退出码 + result.json + 超时/进程树 |
| “为什么保留旧模板表？” | 历史任务可追溯，新任务不再使用 |
| “任务页为什么没有执行池？” | 业务操作与运行状态分离，执行资源在运行监控 |
| “数据统计和工作台重复吗？” | 工作台是行动概览，统计页做 7/14/30 日分析、质量和口径 |
| “当前启用消息队列了吗？” | 展示接口实际返回的 `mode`、`role`，结合消费者启动状态和 Broker 检查回答 |
